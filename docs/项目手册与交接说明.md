## 一、项目概览

- **性质**：纯静态个人博客，无后端、无构建步骤。所有文章数据写在 `js/main.js` 的 `posts` 数组里，由 JS 在浏览器端渲染。
- **部署链路**：本地改文件 → `git push` 到 GitHub → Cloudflare Pages 监听到新提交后 **1~2 分钟内自动重新部署**。中间无需任何手动操作。
- **GitHub 远程仓库**：`https://github.com/Watersterne/SterneSite.git`，分支 `main`。
- **本地 git 状态**：已初始化、已配置身份、已与远程关联，历史提交正常。

### 工具板块技术要点（接手必读）

- **行情数据源**：主源腾讯财经（`qt.gtimg.cn` 实时、`web.ifzq.gtimg.cn` K线，均 `Access-Control-Allow-Origin: *`，浏览器 fetch 直连）；备源东方财富（`push2.eastmoney.com`/`push2his.eastmoney.com`，JSONP）。主源失败自动切换备源。
- **腾讯接口是 GBK 编码**，`js/stock.js` 里用 `TextDecoder('gbk')` 显式解码，不能直接用 `res.text()`（中文名称会乱码）。
- 涨跌配色用 A 股惯例：涨红（#e05252）跌绿（#22a06b）。
- 行情图随明暗主题重绘（MutationObserver 监听 data-theme）。
- 修改行情逻辑后验证方式：`node --check js/stock.js` 查语法；curl 拉真实数据核对字段索引（腾讯实时字段索引：1 名称 3 现价 4 昨收 5 今开 6 成交量(手) 31 涨跌 32 涨跌% 33 最高 34 最低 37 成交额(万元)）。

## 三、日常操作指南

### 3.1 发新文章（Word 方式，推荐）

1. 复制 `posts/新文章模板.docx`，改名（如 `2026-08-08-我的新文章.docx`）。
2. 在 Word 里按格式写：
   - **第 1 行**：标题（必填）
   - **第 2 行**：摘要（可留空）
   - **第 3 行**：分类，写"技术"/"生活"/"读书"（留空默认技术）
   - **第 4 行**：日期 `YYYY-MM-DD`（留空默认当天）
   - **第 5 行起**：正文
3. 正文样式约定：
   - Word"标题 1/2/3"样式 → 转成 `<h2>/<h3>/<h4>`
   - 代码用 **Consolas / Courier New** 等等宽字体（整段等宽 = 代码块 `<pre><code>`，行内等宽 = `<code>`）
   - 图片直接在 Word 里插入 → 自动提取到 `images/posts/`
   - 加粗/斜体自动转 `<strong>/<em>`
4. 保存 Word，**双击 `doc2post.bat`**，输入要转换的文件编号（回车=全部）。
5. 转换成功的 docx 自动移入 `posts/processed/`，避免重复转换。
6. 本地浏览器打开 `posts.html` 预览 → 满意后双击 `deploy.bat` 上线。

### 3.2 发新文章（纯文字骨架方式）

双击 `new_post.bat` → 按提示输入标题/摘要/分类 → 自动在 `main.js` 数组**最前面**插入骨架并自动打开该文件 → 只需补写 content 里的 HTML 正文。适合不含图片的短文章。

### 3.3 手动编辑文章（备用）

直接编辑 `js/main.js` 的 `posts` 数组。字段：`id`（唯一，递增）、`title`、`excerpt`、`date`、`tag`（tech/life/reading）、`tagLabel`（技术/生活/读书）、`content`（反引号包裹的 HTML）。
坑：content 内**不能嵌套反引号**；逗号引号不配对会导致所有文章显示不出来；改完先本地刷新再部署。

### 3.4 部署上线

双击 `deploy.bat`。无改动时会提示无需部署；推送失败时提交仍安全保存在本地，修好网络再跑一次即可。首次推送曾在浏览器弹 GitHub 登录授权（由用户本人完成）。

### 3.5 换首页大图

用任意横版图片覆盖 `E:\Desktop\SterneSite\images\home.jpg`（保持小写文件名），部署即可。

## 四、踩坑记录与硬性约定（接手必读）

1. **bat 脚本必须是纯 ASCII ＋ CRLF 换行**。
   - 原因：cmd 读取 .bat 的编码不稳定（GBK/UTF-8 环境差异），中文会变成乱字节破坏脚本结构（曾出现"系统找不到指定的路径"、退出码 255）；LF 换行同样致命。
   - 约定：bat 里一律英文提示；生成方式用 Python 写 `script.replace('\n','\r\n').encode('ascii')`；**不要用 `chcp 65001`**。
2. **bat 里空输出重定向用 `>nul`，绝不能用 `>/dev/null`**（后者是 Linux 写法，Windows 下报"系统找不到指定的路径"）。
3. **生成 Word 模板必须声明东亚字体**：给 Normal/标题样式的 rFonts 设置 `w:eastAsia`（正文宋体、标题黑体），否则 Word 里部分简体字显示为方框。修复后的模板是 `posts/新文章模板.docx`。
4. **`deploy.bat` 会执行 `git add .`**：博客目录下不要遗留临时/调试文件，否则会被一并提交推送（曾误推 `debug_deploy.bat`，已清理）。
5. **网络**：曾出现 github.com:443 连接超时（curl 28），属临时网络/代理问题；push 失败重试即可，本地提交不丢。
6. git 的 `LF will be replaced by CRLF` 警告无害，可忽略。
